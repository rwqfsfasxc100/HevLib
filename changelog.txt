1.4.3=* If it is a dictionary, uses the following format:
1.4.3.1=* `sensor` -> (String) the sensor name to be fetched with `sensorGet`
1.4.3.2=* `func_method_name` -> (String) the name of a function to pipe the `sensorGet` output through, with it's output being supplied to the formatter
1.4.3.2=* `func_object_path` -> (String) the res:// filepath of a script file, autoload name, or pointers class name for the object to handle the sensor output. ("CurrentGame","pointers.DataFormat","res://path/to/script.gd")

1.4.3.4=* `fallback` -> (Variant) if the sensor returns null (i.e. damaged sensors, sensor doesn't exist), the value to use for formatting instead
1.4.4=* The text string/translation should contain the following to be replaced with the sensor's output: `{sensor:<sensor name>}`, with `<sensor name>` being replaced with the `sensor` property's value
1.5=* `function_outputs` -> (Array) any parameters using the outputs of functions
1.5.1=* Can be used in any context
1.5.3=* Each entry must be a dictionary, and uses the following format:
1.5.3.1=* `name` -> (String) the name used for the formatting string
1.5.3.2=* `func_method_name` -> (String) the name of a function to get the data from
1.5.3.2=* `func_object_path` -> (String) the res:// filepath of a script file, autoload name, or pointers class name for the object containing the desired function. ("CurrentGame","pointers.DataFormat","res://path/to/script.gd")
1.5.3.3=* `extra_operands` -> (Array) additional operands that can be supplied to the function if it needs any
1.5.3.4=* `fallback` -> (Variant) if the output returns null (i.e. intentional output, method returns void), the value to use for formatting instead

[1.16.3]

1.2=* Best use-case is when declaring the variable
1.2.1=* e.g. var pointers:HevLibPointers
1.3=* WARNING: This should only be used when writing in-editor and all cases of the type casting should be removed before releasing a mod
